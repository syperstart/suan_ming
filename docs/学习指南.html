0 · 先看全局：这个项目到底在干什么

一句话概括：它把 Kimi 大模型包装成一个「算命先生陈玉楼」，能聊天、能记住你、能查本地资料、能上网搜。

技术上拆成三件事：

🧠 一个大脑
大模型（Kimi）。它负责理解你说的话、决定要不要用工具、最后组织语言回答你。
🛠️ 一堆工具
查知识库、算八字、抓网页、联网搜索。大模型自己不能上网也不能算八字，只能"伸手要工具"，拿到结果再回答。
📦 一份记忆
存在硬盘上的 json 文件。聊天是"无状态"的——每次请求对服务器都是陌生人，靠读文件才想起你是谁。

请求是怎么跑起来的（鸟瞰图）

↓

↓

最重要的一条规律
数据永远是从上往下传、从下往上回。Web 层不认识大模型，业务层不认识 HTTP，工具层不认识 Web 层。 每层只做自己的事，传的只是一个个普通的参数（字符串、字典）。所谓"参数传来传去"，本质就是上一层把值交给下一层的函数，没有魔法。

1 · 四个文件的分工

文件角色说明
config.py配置中心 只放三样东西：密钥、模型名、接口地址。它不 import 自己的任何文件，所以谁都能安全地导入它。
Mytools.py工具箱 五个工具函数 + 两个共享资源（EMBEDDINGS 嵌入模型、TOOL_MODEL 模型客户端）。严禁 import server.py。
server.py主控 干所有杂活：起 Web 服务、定义 Master 类、管记忆、注册路由。它是唯一 import 别人的文件。
test_kb.py测试脚本 独立于服务，专门用来验证知识库能不能存、能不能搜。你的库里那 3 条测试数据就是它塞进去的。

为什么这么分？——「循环导入」这道坎

你可能会问：为什么不写成一个大文件？因为会踩这个坑：

# 如果 server.py 顶部写 from Mytools import x
# 同时 Mytools.py 顶部写 from server import y
# Python 就会陷入死循环：我要导入你 → 你要导入我 → ... → ImportError

解决办法就是单向依赖：

config.py
最底层，谁都可以用，它谁也不用
↑ 被导入
Mytools.py
可以用 config，可以langchain，但绝不能用 server
↑ 被导入
server.py
最上层，可以用 config，可以用 Mytools
记住这条铁律
箭头只能朝上。以后你写新文件时问自己一句："它会 import server.py 吗？" 会——那就坏了，得把公用部分下沉到 config 或单独文件。

这是解开"参数传来传去"迷雾的关键。我们跟着一句话走完全程。

这里是全项目最核心的 5 步，参数的形状在每一步都在变：
server.py:342-365
def run(self, query, session_id="default"):
    # 字符串 → 字符串
    emotion  = self.qingxu_chain(query)        # ① "depressed"

    # 字符串 → 一段话（语气说明）
    role_set = self.get_role_set(emotion)      # ② "- 你会以温暖、鼓励的语气..."

    # 一段话 → 一个执行器对象
    executor = self.create_executor(role_set)  # ③ 把语气拼进提示词

    # 字典 → 字典 ★★ 关键在这一步
    result = executor.invoke({
        "input":       query,                       # ④-a 用户原文
        "memory_text": get_memory_text(session_id=session_id),  # ④-b 记忆
    })
    answer = result["output"]                   # 从返回字典里取答案

    self.add_memory(query, answer, self.chatmodel, session_id)  # ⑤ 存盘

    return {"emotion": emotion, "answer": answer}
↓
4回到 Web 层，打包成 JSON 返回
server.py:430
return {"emotion": out["emotion"], "response": out["answer"]}
# 注意：内部叫 answer，对外改名叫 response（历史遗留，两个名字指的是同一个东西）
⭐ 最容易卡住的一步：第 ④ 步那个字典
为什么 invoke() 里非要写成字典？因为提示词模板里写着占位符： 
("user", "{input}")                              # 要一个叫 input 的键
("system", "【你们之前聊过的内容】\n{memory_text}")   # 要一个叫 memory_text 的键
字典的 key 必须和花括号里的名字一字不差。少一个就报 InputFormatKeyError，多传入 key 没用到则无所谓。

模型内部那一圈（上面第 ④ 步里面发生的事）

executor.invoke() 不是"问一次就答"，而是一个可能反复好几轮的循环：

轮次 1：思考
模型拿到「人设 + 记忆 + 你的问题 + 工具清单」，判断：我需不需要工具？
↓
轮次 2：伸手要工具
模型的回答不是文字，而是"我想调用 bazi_cesuan，参数是 xxx"
终端里你会看到：Invoking: bazi_cesuan with {...}
↓
轮次 3：执行工具
AgentExecutor 真的去跑 Mytools 里的函数，拿到返回值
↓
轮次 4：带着结果再问模型
工具返回值被记进「草稿纸」，模型看到后决定：还要再调一个工具吗？还是可以回答了？
↓ ↺ 需要就回到轮次 2
结束：给出最终答案
模型输出纯文字，放进 result["output"]
草稿纸是什么？
就是提示词里那行 MessagesPlaceholder("agent_scratchpad")。它记录了「我刚才调了什么工具、工具返回了什么」， 让下一轮询问时模型能想起来。这一行删掉会直接报错，Agent 靠它才能多轮思考。

3 · 专门搞定「参数传来传去」

你说最晕的是这个。其实 Python 传参只有三种形式，不会第四种：

形式例子什么时候用
位置参数 add_memory(query, answer, chatmodel, session_id) 参数少、顺序明显时。必须按定义顺序写。
关键字参数 get_memory_text(session_id=session_id) 参数多、或者想跳过中间某个时用。推荐常用这个，不怕顺序搞错。
字典 executor.invoke({"input":..., "memory_text":...}) LangChain 的约定：一次性传一堆"变量名→值"。key 要和模板占位符同名。

本项目的「参数变形记」对照表

同一份数据在不同层有不同的名字，这是最让人迷糊的地方。对照着看：

它所表示的东西第 1 层（Web）第 2 层（Master）第 3 层（模型）回来时
用户说的话 query query {input} result["output"] → answer → response
会话标识 session_id session_id — 从不返回
历史记忆 — get_memory_text() 的结果 {memory_text} —
情绪标签 — emotion — emotion（原样带回去）

三个「为什么会这样写」的答疑

Q：为什么 create_executor 每次对话都要重新造一个？不能启动时候造好吗？
因为每次的情绪不同，语气就不同，而语气是拼进 system 提示词的。要换语气就只能重造。 这是一个用性能换灵活的设计——好在它很轻量（不重新加载模型，只是拼字符串）。
__init__ 里那个 self.agent_executor 是用「default 语气」造的备用件，目前 run() 并没用它。
Q：self.xxx 是什么？为什么有的函数带 self 有的不带？
self = "这个对象自己"。写在 class Master: 里面的函数叫方法，第一个参数必须是 self， 调用时你不用传，Python 自动填。通过 self.chatmodel 存在对象上的东西，所有方法都能共享。
load_memory()、add_memory() 这些写在 class 外面，叫普通函数，没有 self，直接用就行。
一句话：需要共享状态（模型、工具清单）的就放进类，不需要的就写外面。
Q：为什么到处看到 = "default" 这种写法？
这叫默认参数。调用时不传这个参数，就自动用默认值。 所以 /chat 不写 session_id 也能跑——它自动按 "default" 会话处理， 读写的还是老文件 memory.json，你的旧数据不会丢。

4 · 必懂的 8 个概念（白话版）

① @tool 装饰器
在函数头顶加一行 @tool，就把普通函数变成了"大模型可以调用的工具"。它自动帮模型生成三样信息：
来源作用
函数名工具叫什么，模型就说这个名字
函数正下方的文档字符串最重要！说明书。模型靠它决定"这种情况该不该用它"
参数的 : str 类型标注告诉模型要传什么格式的值
写工具的第一要务
把"""文档字符串"""写清楚。模型看不见你的函数体写了什么逻辑，它只读这段说明。 说明写得含糊 → 模型不知道什么时候该用它 → 表现就是"明明有工具它却说没有"。
② LCEL 管道符号 |
a | b | c 就是 c(b(a(x)))：左边的结果当右边的输入，串成流水线。
例：prompt | model | parser 读作「填好提示词 → 丢给模型 → 把回答解析成纯文本」。
chain.invoke({"input": "你好"}) 就是往管道开头塞数据，拿末端的输出。
③ ChatPromptTemplate 提示词模板
一份带洞的信。{input} 是洞，invoke() 时填进去。
注意 如果你想在模板里写一个真正的大括号（比如 JSON 示例），必须写成双括号 {{ }}， 否则会被当成占位符。SUMMARY_PROMPT 里那行 JSON 示例就是这么写的。
④ MessagesPlaceholder
一个"留白区"，运行时会被替换成一串消息。本项目只用它占位 agent_scratchpad（Agent 草稿纸），不能删。
⑤ AgentExecutor
干脏活的管家：调模型 → 发现模型要调工具 → 真的去执行 → 把结果塞回给模型 → 再问…… 直到模型说"我可以回答了"。
它返回的是一个字典，我们只用 result["output"] 这一项。
verbose=True 让它把每一步打印到终端，排错全靠它——有没有调工具、调了哪个、参数是什么，一目了然。
⑥ Embedding（嵌入模型）
把文字变成一串数字（本项目是 512 个浮点数，叫 512 维）——可以想象成"这段话在意义地图上的坐标"。
意思相近的话，坐标就靠近。所以检索不是比关键词，而是比坐标距离，这就是它能"理解同义词"的原因。
坑 存和取必须用同一个模型。换模型等于换了一套坐标系，新老数据之间距离毫无意义。
⑦ 向量数据库 Qdrant
专门存「坐标 + 原文」的数据库，擅长"找最近的邻居"。
你用的是本地文件版（local_qdrant 文件夹），它靠一个文件锁保证同一时刻只有一个进程能写。 → 所以用完必须 client.close()，服务跑着的时候不能再去写库。
⑧ 模块级代码 & 为什么要重启
Python 里写在 class 外面、函数外面的代码，只在文件第一次被 import 时执行一次。
server.py 第 404-410 行的 MASTER = Master() 就是这样——启动那一刻就把模型客户端、 工具清单、人设文本读进内存并冻结了。此后你改文件，内存里那份不会变。
这条害过你两次
「繁体字去不掉」「明明加了工具它却说没有」——都是因为跑的是旧进程。 改完 server.py / Mytools.py / config.py，必须 Ctrl+C 停掉 uvicorn 再重启。

5 · 记忆系统

为什么要有记忆？

HTTP 是「无状态」的——每次请求对服务器都是全新的一次，它不记得你上一句说了什么。 所以只能把对话写到硬盘，下次请求时读出来，塞进提示词里给模型看。

三层结构（越往上越不容易丢）

第 1 层 · profile 用户档案
{"姓名":"张三","出生年月日":"1998-08-08"}
永不压缩。为什么单独拎出来？因为姓名生辰这种事实一旦被摘要弄丢，后面八字都算不了。
第 2 层 · summary 历史摘要
更早的对话压成 300 字以内的一段话。省 token，也避免上下文越来越长。
第 3 层 · history 最近原文
最近 3 轮原样保留，保证"刚才说到哪"不丢，对话才连贯。

触发压缩的时机

每轮聊天结束后：add_memory() 检查 len(history) > MEMORY_MAX(10) ?
    是 → compress_memory(chatmodel, session_id)   # 让模型读一遍老的，写成摘要+档案
    否 → 什么都不做，继续攒着

压缩做的事：把最老的几条喂给模型 → 模型返回 {"summary":..., "profile":...} → 覆盖旧的、删掉那几条原文、只留最近 3 条。

为什么摘要要用第三人称？
摘要每满 10 条就压一次，压个几十次后，如果让模型用"老夫记得…"这种角色口吻写， 它很容易开始添油加醋编故事。客观记录（"用户叫张三，1998年生"）稳定得多， 而且你打开 json 文件也能一眼看懂。人设交给 system prompt 去管，两件事分开。

会话隔离（session_id）

没有它之前，所有对话共用一个 memory.json，两个人同时聊会互相串台。现在：

def memory_file(session_id="default"):
    sid = "".join(c for c in str(session_id) if c.isalnum() or c in "-_") or "default"
    if sid == "default":
        return MEMORY_DIR / "memory.json"          # 兼容旧数据
    return MEMORY_DIR / ("memory_" + sid + ".json")

那行 join 看着唬人，其实就一句：把 session_id 里所有非字母数字的怪字符删掉， 防止有人传 ../../etc/passwd 这种路径，拼出错误的读取路径（安全问题）。

6 · 知识库（RAG）

RAG 白话讲：先去资料库里翻出相关内容，塞进提示词，再让模型回答。 模型本身不知道你的命理资料，靠这个"开卷考试"。

存资料的流程（以抓网页为例）

1 · 抓网页
WebBaseLoader(url).load() → 拿回一大段 HTML 正文
↓
2 · 切片
每 800 字切一块，相邻两块重叠 50 字。
为什么要切？整页塞进去太长、太杂；切成小块才能精准匹配某一段。
↓
3 · 转坐标
用 EMBEDDINGS 把每块变成 512 维向量（embedding）
↓
4 · 存库
store.add_documents(chunks) 存进 local_documents 集合

查资料的流程

用户提问
"龙年运势怎么样"
↓
问题也转坐标
同一个 EMBEDDINGS 模型，同一个坐标系
↓
找最近的邻居
库里哪几块的坐标离它最近 → 返回那几块原文
↓
塞进提示词
资料 + 问题一起给模型 → 模型"照着资料答题"
两个必须一致，否则存进去查不到
① 集合名：存和取必须同一个字符串（本项目用常量 KB_COLLECTION 统一）。
② 嵌入模型：必须同一个。OpenAIEmbeddings 是 1536 维，你的库是 512 维，硬写会直接报维度不符。

搜索工具带来的「自学闭环」

↓

↓

↓

bazi_cesuan 详解：最容易看不懂的一个

它特殊在工具里又用了一次大模型——用来把大白话变成结构化参数：

# 用户说："我叫张三，1998年8月8日下午2点生"

#   {"name":"张三","sex":"0","year":"1998","month":"8","day":"8","hour":"14",...}

加一个新工具的标准动作（三步）

第 1 步：在 Mytools.py 里写函数

9 · 踩过的坑（按被坑次数排序）

No.1 · 改了代码不重启（坑了你两次）
现象：繁体字去不掉、新加的工具说"没有"、资料存不进去。
原因：uvicorn 进程还跑着旧代码。MASTER、工具清单、路由都是启动时读进内存的。
验证：浏览器打开 http://127.0.0.1:8000/openapi.json，看路由列表有没有你新加的。
解决：Ctrl+C 停掉，重新 python server.py。
No.2 · 本地 Qdrant 的文件锁
现象：AlreadyLocked / Storage folder is already accessed。
原因：本地文件版 Qdrant 同一时刻只允许一个连接。
解决：① 连接用完必须 client.close()（代码里都已改成 try/finally 写法）； ② uvicorn 跑着的时候别调 /add_urls，要批量加资料先停服务。
No.3 · 拼写错误
from_documeents（多一个 e）、text-embedding-3-smell（应为 small）、 from request import（应为 requests）。
Python 不会帮你猜，报 AttributeError / ModuleNotFoundError 时先怀疑拼写。
No.4 · 嵌入模型不统一
库是 512 维的 BGE 中文模型，换成 OpenAI 的 1536 维会报 expected dim: 512, got 1536； 就算维度凑巧一致，不同模型算出的坐标也没有可比性，检索出来牛头不对马嘴。
No.5 · 提示词自相矛盾
人设里同时写着"用繁体中文作答"和"只用简体中文作答"，模型按前面的执行。
改提示词时务必全文搜一遍有无相反指令。
No.6 · 承诺了不存在的工具
人设写"遇到不知道的会用搜索工具"，但工具清单里没有 → 模型只能回答"我没有这个工具"。
人设里说的能力，工具清单里必须真有。
No.7 · 模型输出不守规矩
让它返回 JSON，它偏要用 ```json 代码块包起来，JsonOutputParser 就可能解析失败。
项目里的对策：parse_summary_json() 手动去掉代码块、截取首尾花括号。

10 · Python 语法速查（看到就回来查）

写法意思
from x import y把别的文件里的东西拿过来用
def f(a, b=1):定义函数，b 有默认值，不传就用 1
f(role_set=xxx)关键字传参，指名道姓给哪个参数赋值
self.xxx存在对象上的数据，同类里所有方法都能读
@tool装饰器：给下面的函数套一层额外能力
"""文档字符串"""写在函数第一行，是对函数的说明。本项目里它还是给模型看的说明书
f"我叫{name}"f-string：把变量塞进字符串里
d["key"] / d.get("k", 默认)取字典的值。后者取不到不报错，返回默认值
or 连用（如 a or b or ""）取第一个非空值，项目中大量用来兜底
a[-3:]列表最后 3 个元素（负数索引从末尾数）
[f(x) for x in l]列表推导：把 l 里每个元素过一遍 f，收集结果
try: ... except: ... finally:出错走 except；finally 无论如何都执行（本项目用它 close 连接）
x if 条件 else y三元表达式，条件成立取 x
| 在 LangChain 里管道：左边输出接右边输入（其他地方是"按位或"）
{{ }} 在提示词里转义，表示字面意义上的大括号
